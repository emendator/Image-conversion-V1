## 一、后端数据层（Step 1）

### 1.1 新建 `backend/database.py`

职责：连接管理 + 建表 + 种子数据 + 自愈重建。

- `DB_PATH = os.path.join(config.BASE_DIR, "data", "app.db")`
- `get_conn()`：`sqlite3.connect(DB_PATH, check_same_thread=False)` + `row_factory = sqlite3.Row` + 线程锁。
- `init_db()`：建表 `companies / users / invite_codes / images`（字段见需求文档第五章）；启动时调用；删除文件后下次启动自动重建 + 种种子。
- `seed_if_empty()`：
  - 无公司 → 创建"我的公司"，db_password_hash = bcrypt("<SUPER_ADMIN_PASSWORD 环境变量>")。
  - 无 super_admin → 创建 `admin` / `<SUPER_ADMIN_PASSWORD 环境变量>` / super_admin / company=我的公司 / valid_until=2099-12-31。
- 密码哈希工具可放本文件或 `auth.py`：`hash_password(pw) / verify_password(pw, hash)`（passlib CryptContext bcrypt）。

### 1.2 新建 `backend/models.py`（DAO，可选合并进 database.py）

提供函数式 CRUD：

- `create_user / get_user_by_username / get_user_by_email / get_user_by_id / update_user / delete_user / list_users(company_filter, role_filter)`
- `create_company / get_company_by_name / get_company_by_id / list_companies / update_company_db_password`
- `create_invite_code / get_invite_code(code) / mark_invite_used(id, user_id) / list_invite_codes(created_by)`
- `create_image / get_image / list_images(company_id, category, orientation, keyword) / update_image / delete_image`

> 注意：所有"校验后写"（如邀请码一次性）用单条 `UPDATE ... WHERE status='unused'` 并检查 `rowcount==1`，保证并发原子性。

## 二、后端认证（Step 2）

### 2.1 新建 `backend/auth.py`

- `SECRET`：JWT 签名密钥，存 `data/.jwt_secret`（首次生成，参考 `.secret_key` 生成方式）。
- `create_token(user_id, role, company_id)` → JWT（`pyjwt`，payload 含 sub/role/company_id/exp=7d）。
- `decode_token(token)` → payload；异常返回 None。
- `get_current_user(request)`（FastAPI 依赖）：读 `Authorization: Bearer` → 解出 user_id → 查库 → 校验 `status=='active'` 且 `valid_until > now` → 返回 user；否则 401。
- `require_roles(*roles)`（依赖工厂）：基于 `get_current_user` 的角色校验，403 拒绝。
- 密码/公司密码均 bcrypt。

### 2.2 新建 `backend/routers/auth.py`

- `POST /api/auth/register`
  - 入参：username, password, email, invite_code, action(join|create), company_name, company_db_password。
  - 逻辑：
    1. 校验用户名/密码/邮箱非空、格式（密码 ≥6）。
    2. 取邀请码；`invite_code.status=='unused'` 且未过期，否则 400。
    3. role = 'admin' if level==1 else 'user'；**level==1 才允许 action='create'**；level==2 强制 join。
    4. join：`get_company_by_name(name)` 存在且 `verify_password(db_password, company.db_password_hash)`，否则 400。
    5. create（仅 admin）：`company_name` 唯一性校验；创建公司（存 bcrypt(db_password)）。
    6. 创建 user：role、company_id、invite_code_id、created_by=邀请码创建者、valid_until=邀请码有效期。
    7. 原子标记邀请码 used（`used_by=user.id, used_at=now`）。失败回滚。
  - 返回：成功提示 + 自动登录（可选返回 token）。
- `POST /api/auth/login`
  - 校验密码 → 校验有效期/状态 → 更新 `last_login_at` → 返回 `{token, user:{id,username,role,company_id,company_name,valid_until,last_login_at,expired}}`。
  - 到期/禁用：返回 403 + `detail="账号有效期已到（或已被禁用），请联系管理员延长有效期"`。
- `GET /api/auth/me` → 当前用户信息（含公司名、API Key 是否绑定、有效期天数提示）。
- `PUT /api/auth/api-key`：绑定当前用户 API Key。入参 `encrypted_key+nonce`（复用 `api_config.transit_decrypt`）→ `api_config._encrypt` 加密存 `users.api_key_encrypted`；同时存 `api_base_url/api_model`（可选）。返回掩码。
- `GET /api/auth/api-key`：返回本用户 Key 掩码、base_url、model（复用 `mask_api_key`）。
- `POST /api/auth/logout`（可选）：前端清 token 即可。

### 2.3 全局 API Key 改造（关键）

- 新增 `backend/api_config.py` 辅助函数（或放 auth 模块）：
  - `get_user_api_key(user)` → `_decrypt(user['api_key_encrypted'])`（未绑定返回空）。
- `main.py` 改造：
  - `require_api_key()` → 改为 `require_api_key(user)`：优先当前用户 Key，其次回退全局旧配置（并提示绑定）。
  - `refresh_client(user=None)` / 每次 AI 调用前：`client = BailianImageClient(api_key=当前用户Key, base_url=用户base_url, model=用户model)`（需确认 `api_client.BailianImageClient` 支持构造参数；若从 `api_config` 内部读取，则增加注入点）。
  - 调用链：`generate-ecommerce-final`（颜色修改）、`generate-poster`（异步任务需在任务线程内以**创建任务时的用户上下文**构造 client，`poster_tasks[task_id]` 存 `user_id/company_id`）。
- 前端 `ApiSettingsModal` 文案改为"绑定到当前账号"。

## 三、后端公司 / 邀请码 / 用户管理（Step 3）

### 3.1 新建 `backend/routers/companies.py`

- `GET /api/companies`：公司列表（id/name），供注册"加入公司"下拉（无需登录）。
- `PUT /api/companies/{id}/db-password`：登录 + 角色=admin（且属于该公司）→ 入参 `old_password, new_password` → 校验旧密码 → 更新（bcrypt）。

### 3.2 新建 `backend/routers/invites.py`

- `POST /api/invite-codes`：登录 + 角色校验（level=1 仅 super_admin；level=2 super_admin/admin）。入参 `level, valid_until`。生成随机码（8 位大写字母+数字，排除 0/O/1/I），循环避免冲突。落库 status=unused。
- `GET /api/invite-codes`：super_admin 看全部；admin 看 `created_by=self.id`。
- `DELETE /api/invite-codes/{id}`：仅创建者/超管；仅 unused 可作废。

### 3.3 新建 `backend/routers/admin.py`

- `GET /api/admin/users`：super_admin 看全部；admin 看 `created_by=self.id`（即自己邀请码拉来的用户）或同公司用户（按需求"管理对应的账号"，建议 admin 管自己创建的下级用户）。
- `POST /api/admin/users/{id}/extend`：入参 `new_valid_until` → 更新；同时置 status=active。
- `POST /api/admin/users/{id}/disable`：置 status=disabled。
- `DELETE /api/admin/users/{id}`：
  - 权限：super_admin 可删任意 admin/user；admin 只能删自己创建的 user。
  - 级联：**super_admin 删除 admin 时，先删除 `created_by=该admin` 的所有用户**（事务内完成）。
  - 保护：不可删除自己；不可删其他 super_admin。

### 3.4 定时任务扩展（`main.py` `scheduled_cleanup`）

- 增加：扫描 `users`，将 `valid_until < now` 且 `status=='active'` 的置 `status='disabled'`。

## 四、后端图片库（Step 4）

### 4.1 新建 `backend/routers/images.py`

- 依赖：`get_current_user`（登录），所有查询按 `company_id = user.company_id` 过滤。
- 存储根目录：`主目录/data/image_library/{company_id}/{category}/{orientation?}/`（通过 `config` 新增常量 `IMAGE_LIBRARY_DIR`）。
- `GET /api/images`：入参 `category`（ecommerce/slice/poster_base）、`orientation`（可选）、`keyword`（可选）→ 返回分页列表，每项含 `id/name/orientation/category/created_at/size/uploaded_by/thumbnail`（缩略图 base64，复用 `make_thumbnail_base64`）。
- `POST /api/images`：`multipart`：`file, category, orientation, name` → 校验扩展名/尺寸 → 物理落盘（文件名 uuid，防重）→ 插库（name 冲突自动加 `_1` 后缀）。
- `PUT /api/images/{id}`：改 `name` / `orientation`（校验属本公司）。
- `DELETE /api/images/{id}`：删除记录 + 物理文件（校验属本公司）。
- `GET /api/images/{id}/file`：返回原始文件（FileResponse），供预览/下载/生成器使用。
- 缩略图：列表内联 base64（体积小、简单）即可。

### 4.2 模板迁移与生成器对接

- 迁移：首次启动（或提供一次性脚本 `backend/scripts/migrate_templates.py`）把：
  - `图/电商主图/模板图/*` → `images(category='ecommerce', orientation='vertical'|'horizontal' 按需推断或默认)`，公司=我的公司。
  - `图/营销切片/模板图/横板/*` → `images(category='slice', orientation='horizontal')`；`竖版/*` → vertical。
  - （海报底图无历史数据，无需迁移。）
- `GET /api/templates`、`GET /api/slice-templates` 改造为：从 `images` 表读（按当前用户公司），返回 `{id, name, path(由 /api/images/{id}/file 提供), thumbnail}`。
- **删除** `POST /api/upload-template`、`POST /api/rename-template`（或保留但前端不再使用；建议删除避免双入口）。
- 静态挂载 `/style-images`、`/slice-images` 建议移除鉴权薄弱点，改由 `/api/images/{id}/file` 提供（前端 img src 用该接口 + 携带 token；注意 img 标签无法带 Header，可改用 `?token=` 查询参数鉴权或后端对该接口放行同公司逻辑——实现时选一种，推荐前端用 fetch 取 blob 转 objectURL，或后端提供带 token 参数的 FileResponse）。

## 八、注意事项（防坑清单，源自项目历史教训）

1. **勿吞装饰器**：往 `main.py` 插路由/在模块新增路由时，确认 `@app.*` 装饰器完整（曾误删导致 404）。
2. **AI 调用用量拷贝**：`dict(client.last_usage)` 先拷贝到局部再使用。
3. **model 读取**：`api_client` 默认 model 用 `self.model`（读 api_config），不要硬编码 `config.IMAGE_MODEL`。
4. **异步任务上下文**：海报任务线程内必须用**创建时的用户上下文**（user_id/company_id）取 Key、查底图、存库；勿在任务线程里读全局用户。
5. **事务原子性**：注册 = 创建用户 + 标记邀请码 used，务必同一事务；级联删除 = 删除 admin + 其下级用户，同一事务。
6. **到期判断**：统一 `now` 用 UTC（`datetime.now(timezone.utc)`），存储统一格式（ISO 字符串）。
7. **路径安全**：图片库接口所有文件操作基于库内记录（id 查 filename），禁止拼接用户传入文件名，防路径穿越。
8. **兼容旧前端产物**：`frontend/dist` 需重新 `npm run build` 才能部署生效。
9. **测试勿真跑 AI**：AI 调用花钱；海报改造联调时可用 `use_existing_base` 路径避免文生图（只跑合成）。
10. **seed 幂等**：`init_db + seed` 可重复执行，不重复插入种子。
